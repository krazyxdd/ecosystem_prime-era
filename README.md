# Prime Era — экосистема v2

Экосистема v2 с входом, регистрацией с одобрением владельца, гостевым режимом, профилями с аватарками, правами доступа к каждому модулю и общей доской задач команды.

v1 (соседняя папка) **не тронута** и продолжает работать: данные v2 лежат в той же Firebase, но под отдельным корнем `/ecosystem-v2`.

## Что в папке

| Файл | Что это |
|---|---|
| `index.html` | Главная: приветствие, ваши модули, закрытые модули с кнопкой «Запросить доступ», команда |
| `admin.html` | Админ-панель: заявки, пользователи, матрица доступа, модули, журнал |
| `tasks.html` | «Задачи» — общая доска (канбан, календарь, учёт времени, список). Заменяет Планировщик и Хронометраж |
| `glossary.html`, `objections.html`, `objections-raw.html`, `prime-sales.html` | Старые модули, подключённые к новому ядру (контент не менялся) |
| `planner.html`, `site-time-tracker.html` | Переадресация со старых адресов в «Задачи» (календарь / время) |
| `assets/pe-core.js` | Ядро: вход, права, навигация, профиль, синхронизация, API `window.PE` |
| `assets/pe-core.css` | Оболочка: меню, экран входа, окна, аватарки |
| `РАЗБОР.md` | Разбор багов и удобства: что было не так и что исправлено |

## Первый запуск

1. Залейте папку на хостинг вместо v1 (или рядом, в отдельную папку) и откройте `index.html`.
2. Появится экран **«Первый запуск»**. Создайте аккаунт владельца: фото, имя, фамилия, логин, пароль. В поле «Кем вы были в экосистеме v1» выберите **Саша** — тогда ваши личные данные из v1 подтянутся при входе.
3. Добавьте команду одним из двух способов:
   - **Админка → Пользователи → «Добавить пользователя».** Аккаунт сразу активен. Система выдаст временный пароль и приглашение, которое можно скопировать. При первом входе человек придумает свой пароль.
   - **Человек регистрируется сам** на экране входа. Заявка попадёт в **Админка → Заявки**, где вы выбираете, какие модули открыть.
4. Для тех, кто был в v1 (Андрей, Лина, Лиана), в карточке пользователя укажите **«Имя в экосистеме v1»**. При следующем входе к ним перенесутся личные данные из v1.
5. «Задачи» стартуют с пустой общей доски:
   - каждый сотрудник может нажать «Мои задачи из Планировщика v1»;
   - администратор один раз нажимает «Время из Хронометража v1».

## Как устроены права

- **Владелец** — всё, включая назначение администраторов. Его нельзя удалить или понизить.
- **Администратор** — видит админку и управляет сотрудниками. Не может менять других админов и владельца.
- **Сотрудник** — только модули, отмеченные в матрице «Доступ к модулям».
- **Гость** — главная страница плюс модули с галочкой «Гостям» (Админка → Модули). Остальное — через «Запросить доступ» с контактом. Такую заявку можно превратить в аккаунт одной кнопкой.

Изменения прав применяются **сразу, без перезагрузки**. Это касается выдачи и отзыва доступа, блокировки и одобрения. Заблокированного выкидывает на экран «Доступ приостановлен» на всех устройствах.

## Тестовый режим (ничего не пишется в рабочую базу)

- `index.html?pe2=mock` — вся база живёт только в этом браузере. Удобно, чтобы потыкать регистрацию, одобрение и задачи. Старым модулям тоже запрещено писать в рабочую базу.
- `index.html?pe2=demo` — отдельный корень `ecosystem-v2-demo` в Firebase. Подходит, чтобы потестировать вдвоём с разных устройств.
- `index.html?pe2=live` — вернуться к рабочей базе.

Режим запоминается в браузере. Пока он включён, в меню горит жёлтая плашка **ТЕСТ**.

## Структура данных в Firebase (`/ecosystem-v2`)

```
meta            владелец, дата создания
users/{uid}     профиль, аватарка, роль, статус, доступ к модулям, заявки
auth/{логин}    соль и хеш пароля
requests/{id}   заявки на доступ (сотрудников и гостей)
modules/{id}    включён / для гостей / по умолчанию
audit/{id}      журнал действий
state/{uid}     личные данные модулей (как ecosystem-state в v1)
tasks/items     задачи общей доски
tasks/entries   записи учёта времени
tasks/meta      колонки, цвета тегов, должности, счётчик номеров
tasks/timers    идущие таймеры
taskfiles/{id}  вложения задач (отдельно от доски)
```


## После обновления файлов

Браузеры кэшируют страницы. Если после заливки новой версии что-то выглядит по-старому, обновите страницу с очисткой кэша: `Ctrl+Shift+R`, на Mac — `Cmd+Shift+R`.
